# كاشير المحل الذكي — مشروع Flutter (مصدر أولي)

## تنبيه واضح
الحزمة دي **مش APK جاهز**؛ دي ملفات المصدر ومعاها إعداد GitHub Actions علشان تطلب بناء APK من الموبايل باستخدام المتصفح. البناء الحقيقي ما زال لازم ينجح على خادم البناء قبل ما نعتبر الملف صالحًا.

## طريقة بناء APK من موبايل Vivo فقط

### 1) ارفع المشروع على GitHub
1. افتح `github.com` في Chrome وسجّل دخولك أو أنشئ حسابًا.
2. أنشئ Repository جديدًا باسم `smart-cashier` وخليه Private لو المشروع خاص.
3. فك ضغط `smart-cashier-flutter-source.zip` على الموبايل باستخدام مدير الملفات.
4. من صفحة المستودع اضغط **Add file → Upload files**، وارفع ملفات ومجلدات المشروع كلها، بما فيها المجلد المخفي `.github`.
   - لو واجهة المتصفح مش بتسمح برفع المجلدات، استخدم GitHub من Chrome مع تفعيل **Desktop site**.
   - لازم يكون `pubspec.yaml` في جذر المستودع، ولازم مسار `.github/workflows/build-apk.yml` يكون موجودًا.
5. اعمل Commit على فرع `main`.

### 2) شغّل بناء APK
1. افتح تبويب **Actions** في المستودع.
2. اختار **Build Smart Cashier APK**.
3. اضغط **Run workflow** ثم أكد التشغيل.
4. افتح تشغيل الـ workflow وانتظر انتهاء المراحل.
5. لو النتيجة خضراء، انزل لقسم **Artifacts** وحمّل `smart-cashier-android-apk`.
6. فك ضغط ملف الـ Artifact؛ المفروض تلاقي `app-release.apk` إذا نجح البناء.

### 3) لو البناء فشل
افتح المرحلة الحمراء وانسخ آخر رسالة خطأ وابعتها هنا. ما نتجاهلش الخطأ وما ننزلش APK من بناء فاشل. الـ workflow بيوقف قبل رفع APK لو فشل التنسيق أو التحليل أو الاختبارات أو البناء.

## الصلاحيات
- الكاميرا: لقراءة الباركود فقط.
- الإنترنت: حاليًا ضمن Android Manifest، لا يعني أن البيانات بتترفع تلقائيًا.
- لا نطلب الموقع أو الميكروفون أو جهات الاتصال أو سجل المكالمات.
- قاعدة SQLite محلية على الجهاز.

## اللي موجود حاليًا
- واجهة عربية داكنة بأخضر نيون.
- البيع ومسح الباركود وإضافة المنتج للسلة.
- سجل المنتجات وأسعار الشراء والبيع والكميات.
- حفظ الفاتورة وخصم المخزون داخل معاملة SQLite.
- تسجيل حركات مالية خارجة.
- تقرير أولي لمبيعات اليوم.

## اللي لازم يكتمل قبل الاعتماد التجاري
- مراجعة وتوسيع الاختبارات، وتجربة فعلية على جهاز Android.
- تصدير CSV فعلي ونسخ احتياطي/استعادة.
- تقارير بفلاتر اليوم/الأسبوع/الشهر/الكل وحساب صافي النقدية بعد الحركات.
- شاشة تعديل/حذف منتج ومعالجة باركود مكرر وتجربة أذونات الكاميرا المرفوضة.
- مراجعة المحاسبة: المبيعات والربح والمصروفات وسحب المالك وشراء المخزون أنواع مختلفة ولازم ما نخلطهاش.
- توقيع إصدار إنتاجي بمفتاح خاص محفوظ بأمان قبل توزيع APK على الآخرين.

## تنبيه مالي
اختبر بمبالغ ومنتجات تجريبية أولًا. ما تعتمدش على التقارير الحالية في حسابات المحل الحقيقية قبل اكتمال مراجعة المحاسبة والاختبارات والنسخ الاحتياطي.
